**Why this size.** one property in the root `pom.xml`, the decision that named the snapshot and the overridden
templates checked against the release's own; no code, no contract.

**What must be true.** The records are generated by openapi-generator's release 7.27.0, the first that has
`useRecords`, so the build no longer depends on a snapshot that Sonatype may delete, and a release of the clients is
no longer held back by it.

## Plan

- Set `openapi-generator.version` in the root `pom.xml` to `7.27.0` and drop the comment that says no release has
  `useRecords`.
- The snapshot repository in `settings.xml` stays: the parent and its build tools are snapshots too.
- The template test compares each override's original with the pinned generator's template; it runs first and goes
  red for any template the release moved, which is then copied again with its change.
- Rewrite the decision "The generator is pinned to a snapshot until `useRecords` is released" in `doc/decisions.md`
  to say what holds now, and its index row with it.

## Acceptance

- The full build passes with `7.27.0`, the template test included, and the generated records of both clients and of
  `openapi-records` compile under NullAway and pass their tests.
